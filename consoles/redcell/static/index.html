Redcell offensive

The pentest kit — tool inventory, authorized runners, and a command builder for everything too aggressive to run from here. Authorized use only: your own systems, or written-scope engagements/labs/CTFs.

How this works — start here

Every action that touches a target goes through the authorization gate below. It's enforced server-side, not just a UI checkbox — nothing can run without it, and a separate "lab" box unlocks your own private/local addresses.

Four capability areas:

  • Run — safe runners: fixed argv templates, your target fills exactly one slot.
  • Web — one-click website assessment playbooks, plus an instant header/CORS grade.
  • Password — offline hash identification and a crack-command builder with a wordlist browser.
  • Build — aggressive tools (brute force, exploitation). This only assembles a command string for you to run yourself — nothing executes here.

Arsenal, Tools, History, and Expert round out the kit: the full tool inventory, your own published CLIs, a run log, and a raw-argument mode for anything installed.

Authorization required gate

Every run on this page is gated server-side. Nothing executes without this box checked, and the gate can't be bypassed from the browser.

Safe runner

Fixed argv templates — your target fills exactly one slot. Any other choice you make (scan profile, tags, wordlist) is validated against a server-side list; only the looked-up fixed value ever reaches the command.

Secret / API-key leak scan flagship

      
Scans the page's own HTML, response headers, same-site JS bundles, and the source
        maps those bundles reference for hardcoded credentials — cloud/payment/source-control tokens,
        private keys, JWTs (decoded inline), DB URLs, and 40+ provider key shapes — the single most common
        real-world web leak. Each real leak carries the exact safe, read-only command to confirm it's live
        (built for you to run, never auto-fired). Publishable-by-design keys (Stripe pk_live,
        Google/Firebase browser keys) are called out separately so the report doesn't cry wolf.

      

        

          
          
        

        

          
          
        

      

      
      
      

    


    

      
TLS / cipher deep audit new

      
Dials :443 directly and enumerates which TLS versions the server still
        accepts (1.0–1.3), the negotiated cipher, and the full certificate health — chain trust, expiry,
        self-signed, and hostname match — read even when the cert fails to validate. Legacy protocols and
        a broken cert are graded and called out. One handshake per version, passive.

      

        

          
          
        

        

          
          
        

      

      
      

    


    

      
Tech-stack fingerprint new

      
One passive request, then a signature pass over response headers, cookie names,
        generator tags, and script paths to identify the server, CDN/WAF, CMS, frameworks, and JS
        libraries in use — the first thing to know before choosing an attack surface.

      

        

          
          
        

        

          
          
        

      

      
      

    


    

      
JWT analyzer offline

      
Paste a JWT to decode its header and claims and flag real weaknesses — alg:none,
        HS/RS algorithm confusion, jku/x5u/kid injection surface, and
        expiry problems. Nothing leaves the box; for HS* tokens it builds (never runs) a hashcat/John command
        to crack the signing secret offline. No target, no gate.

      DDoS resilience testing — what this does, and what it deliberately won't
      

        
This tests whether a target's DDoS defenses hold: does rate limiting kick in, is there a
          CDN/WAF absorbing the edge, does latency stay flat under load, where's the breaking point. You get
          a graded read-out with concrete fixes to hand the client.

        
The native probe runs a real, bounded load test — hard-capped in code at 1,000
          requests in flight, 350,000 total, over 180s, and it holds at
          peak so a well-provisioned target actually gets exercised (a few hundred requests won't touch a site
          with datacenter capacity). Pick the tier to match the target — Stress is for real CDN/datacenter
          clients and can hurt a small origin, so use the lighter tiers there. Or pick Custom to set the
          exact request count, duration, and concurrency yourself for a detailed client test (still clamped to
          the caps). Load climbs from gentle and a
          circuit breaker stops the moment a target buckles, so a weak target trips out early. It speaks real HTTP
          over real TCP from your own IP; no packet flood, no spoofing, no amplification. For volume beyond one
          box, the command builder below emits a k6/vegeta/wrk command you run yourself.

        
Same gate as the rest of Redcell: the authorization box is required, the opsec gate
          refuses to fire while your real IP is exposed, and ownership verification (optional) stamps the
          report with proof you control the target.

Expert run gate

      
Run any installed tool from your kit with your own arguments. Arguments are split into a
        real argv and executed directly — never through a shell, so nothing can break out. Only your
        pentest tools are runnable here (not arbitrary system commands). You own the target choice — same as
        your terminal, so only point it at what you're authorized to test.
