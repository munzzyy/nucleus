Operator cheat sheet
Search operators — what each one does
site:restrict to one domain — scopes everything
inurl:term appears in the URL path
intitle:term in the page <title>
intext:term in the page body
filetype: / ext:restrict to a file extension
"exact phrase"quotes force an exact match
-termexclude results containing term
OR / |either term matches
*wildcard for an unknown word in a phrase
before: / after:date-bound results (Google)

The skill is stacking them: site:target.com filetype:env intext:"api_key" is a completely different question than any part alone.

No engine actually speaks Google's dialect, so each dork is translated per engine before it opens: Bing and Brave want inbody: not intext:; Yandex calls filetype mime: and title title:, and has no inurl: at all; DuckDuckGo reliably honors only site:. When an engine has no equivalent for an operator a dork uses, its link is dimmed and marked ~ — the query still runs, but that operator is ignored, so trust the result less. before:/after: are Google-only. Dead operators (cache:, link:, related:) are left out on purpose — Google dropped them.
